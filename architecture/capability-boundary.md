# Capability Boundary

This document explains the semantic boundaries between Capability and
adjacent enterprise concepts.

## Boundary Analysis

Per CR-ES-002 §3 + ADR-ES-002 §1.2, Capability is distinguished from:

- Entity: Capability is an ability possessed by an Entity
- Role: Role identifies responsibility; Capability identifies ability
- Process: Process describes how work is performed; Capability describes
  what can be achieved
- Function: Function describes an area of responsibility/activity; Capability
  describes ability
- Outcome: Capability enables or contributes to an Outcome; it is not the
  Outcome
- Resource: Resource supports a Capability; it is not the ability itself
- Service: Service exposes or delivers capabilities through an
  interaction/offer
- System: System may implement or support a Capability
- Value: Capability contributes to Value but is not itself Value
- Goal: Capability may enable achievement of a Goal
- Skill: Skill may contribute to a Capability but does not necessarily
  represent the enterprise-level ability

The principal semantic distinction is:

Capability answers "what can be achieved?" while Process answers "how is
it performed?"
